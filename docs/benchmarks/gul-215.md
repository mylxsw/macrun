# GUL-215 validation

Measured on 2026-10-05, macOS 26.6.2 / arm64, Rust 1.98.0, optimized release binaries. Baseline: `ba326790ea0cc24038e69dc1187496104f05fae7`; candidate: this PR. Three alternating baseline/candidate pairs used fresh disposable loopback QUIC server/worker instances. No build or other validation process owned by this run ran alongside those pairs. The host was shared, and filesystem timing varied substantially. These are synthetic local results, not a WAN throughput claim or a p95/p99 estimate.

Initial small-file sync remains sensitive to per-file fsync and host load; no compression/pack speedup is claimed. A changed large file still transfers all 67,108,864 bytes. Two backend tool calls still share the desktop lock, so the 600 ms of fixture sleep is intentionally serialized.

## Deterministic outcomes

- Each 64 MiB download/upload creates **one** worker task, versus **128/130** at baseline. Raw streaming replaces 512 KiB stop-and-wait RPCs.
- Status-only polling omits result images; reference responses omit base64. Two MCP reads of the same completed image task make exactly **one** binary artifact download. Legacy `task.get` still returns the full inline image by default.
- MCP ping can complete while another request waits for a task. Two independent roots can sync concurrently on one worker. A running command excludes sync to its workspace without disconnecting the worker, and sync succeeds after the command is cancelled.
- A 110,000-entry manifest exceeding the old 16 MiB frame limit round-trips through pages. Interrupted uploads resume from a verified prefix, retain destination atomicity, and create one history record per attempt.

## Checks

- **54 core Rust tests passed**, including nine new performance/protocol regressions; `cargo fmt --check` and all-target Clippy with `-D warnings` passed.
- **33 desktop Rust tests passed**, with the worker sidecar prepared through the repository script. The desktop dependency lock includes the new native watcher dependencies.
- Real QUIC `scripts/smoke.py`, `scripts/multi-smoke.py`, and `scripts/perf-probe.py` passed. The shared-cwd dedup smoke now waits for its first command because workspace writes are exclusive; concurrent independent roots and conflict rejection have separate assertions.
- Linux amd64 Docker server/CLI → Mac arm64 worker passed sync, incremental content, command execution and MCP image checks, with both the current image and the pre-existing legacy `macrun:generic-demo` image. The harness reads the changed host file through the container first: this Docker bind mount refreshes cached stat metadata lazily. This establishes the Linux source view before testing Macrun; it is not an application retry or a hash-check bypass. Use `--strict` on filesystems with unreliable metadata.
- `cargo-llvm-cov` across the core tests and the three local integration scripts: **85.76% line**, **81.40% region**, **84.34% function** coverage. No source exclusions. These are core runtime metrics, not desktop or branch coverage.

Coverage reproduction (requires `cargo-llvm-cov` and LLVM tools):

```sh
./scripts/cargo-local.sh llvm-cov --locked --no-report
export LLVM_PROFILE_FILE="$PWD/target/llvm-cov-target/macrun-%p-%10m.profraw"
python3 scripts/smoke.py target/llvm-cov-target/debug/macrun
python3 scripts/multi-smoke.py target/llvm-cov-target/debug/macrun
MACRUN_PROBE_PROFILE=instrumented-debug python3 scripts/perf-probe.py target/llvm-cov-target/debug/macrun
./scripts/cargo-local.sh llvm-cov report
```

No production machines or real computer-use backend were exercised. WAN RTT/loss shaping, production percentile latency, real screenshot capture/encode time and Xcode cold/warm build workloads remain unmeasured. Block deltas, small-file packs, persisted history indexing, resource-group configuration, UI sequences, video and transport replacement remain the measurement-driven follow-ups from the architecture review; this PR implements the core stages 1–3.
