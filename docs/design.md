> [!summary] 实现原则
> 用最短路径验证 Linux 改代码 → Mac 构建运行 → agent 看图并操作的完整流程。保留 Rust、QUIC、Cua Driver；先做按文件增量同步和明确的失败恢复，不实现块级同步、完整配对体系或代码执行隔离。

行为与验收以 [需求文档](requirements.md) 为准。更新日期：2026-10-01。本文描述 demo 的实现方案，尚未完成实机验证。

## 技术选择与职责

| 组件或选择 | Demo 职责与理由 |
| --- | --- |
| Rust 共用协议库 | server、CLI、worker 共用消息类型和文件校验代码，保持既有选择；不主张已经证明比其他语言更快 |
| QUIC 长连接 | worker 主动拨出，控制、文件、日志分流；实际跨国 UDP 可用性先实测 |
| server | 接受本机 CLI 请求，读取 Linux 工作区、发送增量文件，维护当前任务并保存日志与结果 |
| CLI | 提交结构化命令、显示实时日志、返回结果位置；不承担长连接生命周期 |
| worker | 维护镜像、执行构建测试、启动与跟踪应用、转发 Cua 调用 |
| CuaDriver.app | 常驻提供窗口观察和输入，避免重复实现桌面驱动 |

QUIC 避免不同流之间的队头阻塞，但不能消除同一流的顺序等待、拥塞或带宽限制。Rust 和 QUIC 是本轮选择，不作为未经测量的性能结论。若真实链路 UDP 无法使用，先记录阻塞原因，再决定替代传输；不预先实现双协议栈。

Demo 信任传入工程、测试和应用。结构化参数便于重现调用，不能限制这些代码在 Mac 上执行的逻辑。安全产品化工作不进入本轮关键路径。

## 首轮实施顺序

1. **本机能力验证**：在 Mac 上用目标 Xcode 工程构建、按绝对路径启动，通过 Cua 观察、点击和输入。确认可用版本、权限、后台动作和窗口坐标。
2. **真实链路验证**：Linux server 与 Mac worker 建立 QUIC 长连接，传一个文件、实时日志和一张 PNG，记录耗时与重连行为。
3. **接通 run**：同步、构建、定位产物、启动、观察、写回 result.json。
4. **接通迭代操作**：run/window/snapshot 身份、ui 命令、停止、取消与失败处理。
5. **实际项目验收**：执行需求文档的案例。通过后再补 Swift Package build/test，按测量结果决定优化。

每一步都先得到可检查的真实输出。Cua 不可用、项目无法本地构建或 UDP 链路不通时，先解决该项，不继续堆叠完整框架。

## 连接与消息

CLI 通过 Unix socket 与 server 通信。worker 主动连接配置的服务器，使用手工配置的证书信任与共享令牌；不提供 enroll 命令。实现使用 QUIC 库已有 TLS 配置，不自行设计密码协议。

一条连接中至少分离控制流、文件流、日志/结果流。限制并发文件传输与缓冲大小，及时读取控制和日志，避免大文件占满应用缓冲区。流式读取文件、计算哈希并写盘，不把整个工作区加载到内存。每条任务消息带 job id；注册消息带协议版本、worker 实例 id、当前任务、清理状态、运行会话与工具版本。协议不兼容时拒绝注册并说明版本。

双方每 5 秒发心跳，15 秒无对端数据判定断开；重试间隔 1、2、4、5 秒，之后最大 5 秒。每次连接尝试设置 5 秒超时。网络恢复到就绪的耗时包含断线识别、重试、握手与旧任务清理，记录实际值，不保证固定 5 秒。

连接成功不等于可接任务。worker 先核验或清理遗留执行状态，再报告 ready。普通任务必须同时取得 server 与 worker 的空闲状态；新连接注册后旧连接失效。

## 同步实现

镜像路径保持固定，DerivedData 放在独立固定目录。server 扫描 Linux 工作区得到本轮清单，包含相对路径、类型、大小、内容哈希、可执行位或符号链接目标。

正常同步以成功清单判断候选变化，并校验必要的目标状态；恢复同步重新核验实际磁盘内容。第一版按变化文件传完整内容，无需滚动校验、分块重组或 zstd。协议保留文件大小与哈希即可，压缩之后按测量收益增加。

同步步骤：

1. 检查源目录扫描结果与目标文件系统的路径冲突；demo 要求同步期间暂停编辑。
2. 持久化 `sync_incomplete` 标记及本次计划管理的路径，然后才开始修改镜像。
3. 变化文件写入临时文件，核对大小和哈希，通过后替换目标；保留可执行位。
4. 删除旧成功清单及未完成计划中曾管理、本轮已不存在或被排除的路径。保留其他生成文件；处理文件/目录转换时若遇到无法保留的未管理内容，返回 path_conflict，避免直接递归删除。
5. 再次检查源文件变化；发现修改则本轮失败，下轮重新扫描。
6. 持久化新清单，最后清除未完成标记，允许构建。

未完成计划也要保留：否则首次同步新增了 A 后中断，Linux 随后删除 A，旧成功清单不知道 A 存在，恢复时就会留下多余源码。新清单和计划的写入使用临时文件替换；标记清除发生在清单落盘之后。

这不是整目录事务。中断后部分文件可能已经更新，worker 用标记禁止构建，下一轮修复。worker 崩溃后发现标记时也执行相同流程。只保留旧清单不足以证明源码完整。

内部链接保留或改写为镜像内相对链接，外部链接跳过并列入结果；默认排除与路径规则遵循需求文档。没有实现持续编辑时的一致快照；对检测到的变化明确失败，不能声称整个工作区被原子冻结。

## 任务状态与清理

任务主状态为 `accepted → syncing → building/testing/launching/observing/acting → succeeded`，按命令跳过无关阶段；任意阶段可进入 `cleaning → failed/cancelled/timed_out`。任务失败与 worker 是否 ready 分开记录。

server 保存 job 状态与日志位置，worker 在启动子进程前记录任务，启动后记录进程组及身份。退出码由需求文档统一映射，具体原因放在 error.code。日志生成后持续发送并写盘，不能等任务结束才集中上传。

- CLI 断开：任务继续，结果写入原目录。
- 网络断开：server 标记失败；worker 检测断线后取消活动任务，先请求进程组退出，5 秒后必要时强制终止并回收。
- 超时或 cancel：采用相同清理流程，清理完成才允许新任务。
- server 重启：未完成任务标为 server_restarted；注册时要求 worker 清理相应任务。
- worker 重启：核验遗留进程身份和同步标记。可以确认身份的遗留任务先清理；无法确认时报告 recovery_required，由人工处理。
- 结果丢失：不自动重放 ui；动作状态记 unknown，恢复后重新观察。

进程组清理覆盖普通构建/测试子进程；主动脱离进程组的特殊项目不承诺自动清理。demo 遇到这种情况保持非 ready 并人工处理，不扩展成通用进程管理器。

status 始终可查询 server 已知状态，并标注 worker 数据采样时间。cancel 是独立控制请求，stop 是普通应用生命周期任务。server 不因“已标记失败”就忽略 worker 清理状态。

## 构建与应用生命周期

worker 根据 macrun.toml 组装 xcodebuild 参数，固定 project/workspace、scheme、configuration、macOS destination 和 DerivedData。支持测试标识过滤，保留项目已有签名设置。构建日志、测试日志与服务诊断日志分别存储。

第一版要求明确 app_relative_path，以 DerivedData 为基准解析。构建成功后检查对应 `.app` 和可执行文件，再按绝对路径通过 macOS 应用启动 API 启动，获取实际进程身份；Rust 可调用系统框架，不要求另造 Swift 桌面驱动。

记录 `run_id`、应用绝对路径、bundle id、pid、进程启动时间。只接受确认属于本次启动产物的实例；发现已有同 bundle id 实例而无法区分时返回 app_instance_conflict。运行会话独立于 job，观察失败不丢弃已经启动的会话。

新的 run 完成构建和产物检查后才停止旧会话。停止核验进程身份，先正常退出，5 秒后必要时终止；然后启动新实例。构建失败保留旧应用，启动失败不自动回退。应用退出、stop、重新启动都会使旧快照失效。

成功运行的应用在网络断开时可以保留；活动 run 在断线时若已创建新实例但任务未结束，worker 清理该新实例。重新连接后对保留的会话核验身份并重新观察；不使用之前缓存的窗口 token。

## Cua 接入与窗口模型

安装 CuaDriver.app 并以应用身份启动 daemon，将辅助功能和屏幕录制权限授予该应用。worker 连接常驻 daemon，不对每次点击重新冷启动驱动。先用官方支持的本机接口打通，具体适配接口与所选版本一并记录。

Demo 使用已安装 daemon 的正常权限模式，不要求 bounded 清单。产品化采用 bounded 时，必须在拥有运行时的进程启动时配置，连接方不能改变正在运行的 daemon 模式。

截至本次资料核对，公开 Skill 页面显示 0.30.4，旧文档引用 0.31.0；不据此猜测最终安装版本。实施第一步记录实际二进制版本、安装来源和可获得的 commit，并固定验证通过的版本。升级 Cua 或 macOS 后重跑关键用例。

上游测试可帮助选择首轮用例，但不能替代目标项目实测：

| 类型 | 上游已记录的能力 | 本轮需要注意 |
| --- | --- | --- |
| AppKit | 后台左键、设值、输入、部分坐标点击与滚动 | 后台滑杆拖动被拒绝，部分按键组合尚未证明 |
| SwiftUI | 后台左键和设值 | 测试中的临时 popover 面板不在目标 AX 枚举中；其他输入需实测 |
| WKWebView / Tauri | 多种后台点击、输入、按键和滚动 | 后台拖动被拒绝 |
| Electron | 多种后台点击、输入和按键 | 后台滚动与拖动被拒绝 |

macrun 自己维护快照映射：`snapshot_id → run_id + window_id + 窗口尺寸 + Cua 观察/token`。动作校验映射后消费快照，执行并重新观察。多窗口逐个显式选择；切换观察导致上游 token 失效时，相应本地映射也失效，不能假设上游支持跨窗口 token 长期共存。

窗口内 point 坐标转换使用该次观察的原点与比例，保留 x/y 两轴信息，不把缩放 PNG 的像素直接传入驱动。目标窗口消失、尺寸变化或进程变化时要求新观察。Cua 接受动作和业务效果成立分别记录，effect_verified 默认 false，由 agent 查看结果判断。

默认不自动切前台。只有配置开启且明确收到 background_unavailable，才重试一次前台，并记录原拒绝原因和实际 delivery。前台可能影响焦点与鼠标；其他失败不重试。动作接受后观察失败保留 accepted，防止调用方误以为“没点上”而重复操作。

后台能力依赖上游实现和 macOS 兼容性；macrun 仍负责版本固定、适配测试和必要回退。不依赖 cua-perception、Lume 或 Fleets。

## 性能与结果

先保留收益明确的措施：常驻连接、按文件增量、日志流式传输、固定构建缓存、常驻 Cua、截图缩小。暂不实现块级差量、强制压缩和专门的低内存调优。

结果按 job 保存到 Linux `.macrun/artifacts/`，字段、错误码和命令以需求文档为唯一约定。服务诊断日志记录阶段、耗时与错误；原始构建/测试日志可能包含源码片段，不做“所有日志绝不含源码”的承诺。截图与控件树本来就是结果文件。

性能测量区分扫描/哈希、传输、构建、等待窗口、捕获和回传。记录原始数据量与 PNG 字节数，仅限制截图长边不能保证固定回传时长。例如 5Mbps 链路两秒理论传输量约 1.25MB，实际还要扣除其他开销。

首轮每个固定场景至少测 10 次，报告中位数和最大值。是否增加 zstd、大文件分块或截图编码选项，依据真实数据决定；不在功能验证前把参考耗时写成硬门槛。

## 完成标准与后续

完成标准是需求文档的 demo 验收在真实链路和实际项目上通过，且结果可以检查。编译成功不能代替窗口启动证明，驱动返回成功不能代替业务效果观察。

产品化再讨论身份管理、隔离与权限、隐私、事务同步、无人值守恢复、多项目和性能 SLA。本轮只补足完成一次真实开发迭代必需的功能与失败反馈。
