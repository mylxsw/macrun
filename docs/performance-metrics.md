# 本地性能历史

桌面应用侧栏的「性能」页面可按最近 1/7/30/90 天、服务器、项目、操作和状态筛选历史，查看数量、成功率、成功任务 p50/p95/p99、图片产物大小和传输载荷。点击记录可查看 Mac 与服务器各自的阶段、声明输出和传输速度。执行器停止、服务器断网时仍可读取本机索引；看历史不会启动连接或读取钥匙串。

这是 GUL-220 方案的 P0 实现。CPU/RSS、慢文件排名、长周期汇总、前端最终交付时间和外部 exporter 属于后续诊断扩展。

## 声明命令输出

```sh
macrun exec --cwd /path/to/project --output 'build/*.zip' --output build/MyApp.app 'make build'
```

`exec.start` / MCP `exec_start` 也接受 `outputs` 数组。最多 32 项，每项最多 1024 字节；支持相对路径和 glob。完成命令后，只读取文件元数据，不读取或传送输出文件内容。测量使用实际执行目录，包含 snapshot 副本；它表示测量时存在的文件大小，不推断哪些内容是本次新生成的。

目录按 regular file 的逻辑大小累计；每项内部及合计按 inode 去重，避免 hard link 或重叠声明重复计数。不沿符号链接遍历，也不允许绝对路径、`..` 或中间链接越出工作区。单次测量限 5 秒、10 万目录项。缺失、无法读取、无效 pattern、越界和超限分别显示状态，未声明或未完成测量不会显示为 0 B。

## 口径

- 总耗时和阶段耗时使用本机单调时钟；不将两台机器的时间相减。阶段为可重叠的累计 wall time，另存次数与最大值，不能直接相加。命令记录审批、执行容量、snapshot、进程、日志收尾与产物测量；桌面任务记录资源、后端锁、启动与工具调用；同步记录清单、扫描、哈希、打包/解包、接收安装和提交。
- 命令总耗时从本机接受任务时开始，到生成终态摘要为止；不包含写入该摘要本身的耗时。同步本机计时包含清单协商；服务器计时包含初次扫描与源文件再次确认。扫描/哈希计数是累计工作量，多次确认可能重复扫描相同文件。
- 业务任务数按接收时间筛选，使用半开区间 `[from_ms, to_ms)`。序列子任务与 `artifact.download` 尝试可查询，但不重复计入业务任务数。序列父记录的图片大小不与子记录再累计一次。
- 延迟样本只包含在筛选窗口完成、状态为 succeeded、测量完成的顶层任务。跨窗口任务可贡献完成延迟；取消、拒绝和旧记录不作为成功延迟。多服务器合并原始延迟样本求分位数，不平均各服务器 p95。
- 成功率分母为 succeeded + failed + timed_out + unknown；取消和拒绝单列，仍在执行的任务不计入分母。旧任务只计数量，缺少性能数据时显示「未采集」。无延迟样本的趋势区间留空。
- `payload` 仅统计实际成功读取/写入的文件、delta 或压缩 pack 数据，不含 JSON/帧控制字节。失败前的部分 I/O 保留。`control_rx` / `control_tx` 是观测范围内的应用层控制帧，不是网络线速或 QUIC 重传字节；服务器与 Mac 字节各自保存，汇总只用 Mac 侧。
- `full_file`、已验证 `resume_offset`、本次 `payload` 和接收端 `confirmed_logical` 分开。worker 下载发送成功不代表客户端最终 fsync/发布完成，因此不伪造下载 confirmed；前端最终交付统计留作后续扩展。
- 载荷总量及载荷趋势按尝试接收时间归属，包含失败尝试，不表示每个日历桶内精确发生的网络流量。详情采样最多每秒一条、最多 600 条并保留末尾累计值；速率曲线为采样区间平均速率。平均速度使用首末成功 payload I/O 时间窗；单次 I/O 或零时间窗不能计算速度。RTT 是任务起点的连接级观测，TCP/TLS 不提供时显示未采集。
- 大于 JavaScript 精确整数范围的计数以十进制字符串返回；JSON/CSV 导出保留精度。

## 持久化与导出

任务 `result.json` 是权威记录，`metrics.sqlite` 是可重建的 WAL 查询索引；列表索引只存紧凑摘要，详情从指定任务读取采样和输出。图片下载尝试另存 `metrics-attempts`，不会新增业务任务或影响任务调度。数据库、WAL/SHM 和 journal 保持私有文件权限，不保存命令、环境、原始输出、图像内容或绝对项目路径。项目使用本机 keyed hash 与目录名称标识。

新 worker 宣告 `performance_metrics_v1`；新 server 仅对支持它的 peer 回传白名单数字指标。服务器 outbox 按已认证 client 隔离，最多 1000 条，重连后重试，7 天过期。报告只能合并至本 profile 已登记并进入终态的 job，不创建任务，不改变任务状态。旧 peer 保持原有协议。

启动时从权威记录幂等重建/校正索引。损坏数据库保留一份私有诊断副本并重建；较新 schema 不降级。索引写入失败不改变任务结果，并标记汇总可能不完整，重启执行器可修复。历史清理沿用 7/30/90 天策略，删除任务/尝试时同时清理索引并保留既有 dedup tombstone；曲线在 7 天后清理。

「导出 JSON / CSV」打开原生保存窗口。Rust 将当前过滤范围内的全部摘要流式写入用户选择的位置，包含版本和清晰的字段单位，不把全量历史传进 WebView，也不只导出当前页。写入失败保留原目标文件；CSV 转义换行/引号并防止公式注入。检测到索引不完整时先提示修复再导出。

## 验证

`make check` 覆盖 Rust 格式、clippy 和单元/集成测试；`npm test` / `npm run build` 覆盖桌面组件和生产前端。新增用例覆盖真实命令的 stdout/stderr/输出大小、失败与续传的部分字节、多 profile 分页与分位数、旧数据、终态报告重放、索引损坏/锁定/较新 schema、输出越界/hard link/glob、保留、精确整数和原子导出。实际 QUIC 与 TCP/TLS smoke 包含 server report 合并及 worker 重启/停机后的索引读取。

可运行 `cargo run --release --example metrics_query_probe` 复现合成索引查询基准：在 Apple M4 arm64 上，10 万条记录、8 次查询，dashboard p95 为 138.30 ms，detail p95 为 5.70 ms。数据通过事务生成于隔离临时目录；这是合成索引查询测量，不是完整任务存储重建基准，也不是采集前后的 A/B 开销结果。不同硬件、记录规模与负载需另测，未宣称采集开销或 idle CPU 预算达标。

原生调试 `.app` 已可打包；浏览器夹具使用真实 React 看板验证 1280×900 与 760×580 窗口、详情、无页面异常和横向溢出。夹具响应是模拟数据，不替代原生保存窗口的人工交互验收。
