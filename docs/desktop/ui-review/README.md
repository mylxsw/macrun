## 旧用户首次进入的引导优化

2026-10-04 后续反馈：旧执行器用户打开桌面版时，直接看到配对码页面，容易误以为必须重新配置服务器。沿用 v2 的设置页和迁移确认框，调整首次入口及提示位置：

| 本机状态 | 打开后的页面 |
| --- | --- |
| 已有桌面版连接配置 | 现场首页；按已有偏好自动连接 |
| 尚无桌面配置，但旧服务已加载或原启动配置仍在 | 设置页顶部显示“检测到旧版 Macrun”和“已有配置，无需重新配对”，可直接点击迁移 |
| 没有桌面配置，也没有旧服务或原启动配置 | 原有配对向导 |

旧服务未运行时仍能发现配置，包括指向有效配置文件的链接；已经停用的 `.macrun-disabled` 备份、目录或断开的链接不会被当作待迁移配置。迁移不会自动执行，确认框取消后入口保留，失败时显示错误与重试，成功后单独启动连接。配对命令框恢复原稿字号和上下间距，避免全局终端样式覆盖。

![旧用户首次进入设置页的顶部迁移提示，模拟数据](images/onboarding/legacy-running.png)

上图来自本机 Chrome 访客窗口中的真实 React 组件，使用明确标注的内存测试夹具，不代表又执行了一次正式迁移。浏览器交互已检查新用户、旧版运行中、旧版已停止、已有桌面配置，以及迁移取消、失败、成功与后续启动。760×580 视口的 DOM 布局核验确认迁移按钮完整位于首屏、没有横向溢出。

补充截图：[发现已停止的旧版](images/onboarding/legacy-stopped.png)、[迁移错误及重试](images/onboarding/migration-error.png)。

安装后的启动复查还发现：钥匙串等待系统授权时，`start_worker` 持有进程锁，导致主线程上的 `app_state` 一起阻塞。已将凭据读取移到后台且不占用进程锁，防止重复启动发起多个授权请求，并在读取完成后重新检查退出、迁移、配置变化和现有进程。保留系统授权，不调整钥匙串权限。

本次前端 38 项测试和原生 12 项测试通过，TypeScript、生产构建及桌面 Clippy 通过。

最终 release 包已更新到 `/Applications/Macrun Desktop.app`，本地 ad-hoc 严格签名校验通过，安装与构建副本哈希一致。实机确认重新打开直接进入现场，等待钥匙串授权时可正常切换到设置页；没有再卡住界面。当前系统授权仍待用户完成，因此本次安装后的服务器重连尚未验证。正式配置、1495 条旧任务和 20 份同步状态的保留检查通过；未再次迁移、未修改钥匙串授权规则。
