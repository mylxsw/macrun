# 桌面客户端执行计划

状态：以下为原执行基线。当前功能实现与验收进度见 [完整验收清单](completion-checklist.md)，代码入口见 [桌面开发说明](../../desktop/README.md)。未完成原生验收的项目不勾选完成。

## 目标与范围

让用户通过桌面应用配置连接、管理本机 worker、查看任务进展。先交付 Mac 体验，同时为 Windows 隔离平台差异。现有 Linux 服务端继续运行，保留 CLI/MCP 能力。

本阶段不引入商业计费、托管连接服务、多租户、设备集群或自营算力。无需因为桌面界面而重写现有传输及执行核心。

## 建议架构

- Tauri：窗口、托盘、应用生命周期和本机控制。
- 共用前端：概览、任务记录、连接设置；具体前端框架与状态管理库待定。
- Rust worker：独立进程，随应用打包，继续负责连接、任务、同步和本地 MCP 后端。
- 应用通过结构化本地消息获取快照和任务事件，不从展示日志反推业务状态。IPC 具体方式在技术验证阶段确定。
- 控制入口仅供本机应用使用，验证调用方，避免无意增加公开监听端口。凭据存储方式需在实现前确定，不放入前端日志。

独立 worker 是建议，不是用户已经批准的进程协议。正式开发前应核实现有状态来源和暂停机制，形成接口约定。

## 实现原则

- 不自动重跑结果不确定的有副作用任务；沿用任务编号去重规则。
- 传输连接状态、worker 状态、桌面后端状态分别建模。
- 菜单栏图标不等于进程保活；注销、休眠、退出的限制应如实展示。
- 不用虚构百分比表示无法测量的任务进度。原型中的进度条仅是示意，正式版优先使用阶段与已耗时。
- 统计来自真实任务事件；实现前明确任务编号、终态、时区和重连补录规则。
- 运行修改按贡献指南执行 `make check`、`make smoke`；另做真实远程与原生 GUI 验证，不能互相替代。
