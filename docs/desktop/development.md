# 桌面开发记录

2026-10-04：用户要求重新读取全部 v2 设计后开始开发。

## 本轮工作顺序

1. M0：worker 本机控制协议、暂停、全部停止、桌面总开关、状态与事件；回归测试。
2. Tauri 应用与 v2 四页界面、托盘及全局停止快捷键；真实数据接入。
3. 验证 sidecar 生命周期、独立测试环境与本地 QUIC 链路；记录完成与未完成范围。

采用 React + TypeScript + Vite；Rust sidecar 保持独立。本机 IPC 使用私有 Unix socket，控制命令不通过远端工具开放。开发和验证不接管现有 LaunchAgent 或生产服务器。

本轮优先形成 M0 可运行纵向链路。M1 的一次性配对／钥匙串、旧服务迁移属于后续功能阶段；P1 的命令审批、路径限制与屏幕提示不以假开关代替。原设计文件保持不变。

## 已落地

- `desktop/`：Tauri 应用、React 四页界面、菜单栏面板和全局停止快捷键接线。
- `src/local.rs`：私有 socket、同用户检查、独占锁、状态订阅和固定控制命令。
- worker：真实暂停、桌面调用总开关、全部停止、同步任务进度、父进程管道生命周期。
- engine：任务事件、环境变量参数遮盖、带密钥请求指纹及重复请求兼容。
- 配置、日志入口、退出确认、旧 LaunchAgent 冲突检查。原有 CLI 模式保留。

## 验证记录

- 核心 Rust 检查及 15 个测试通过；前端 3 个状态/筛选/日期测试通过，TypeScript 和 Vite 构建通过。
- 原有 `make smoke PROFILE=debug` 通过，覆盖命令、文件、同步、MCP、重连及日志检查。
- `scripts/desktop-smoke.py` 通过真实本机 QUIC + IPC 联调：暂停及重复请求、同步进度、桌面控制门禁、全部停止、父进程退出清理、重启后的策略。
- 联调发现并修复 Tokio 标准输入读取导致退出等待的问题，改由独立线程监测父进程管道。
- 开发版 macOS `.app` 构建成功。电脑操作工具拒绝访问新应用，因此窗口视觉、托盘操作、全局快捷键、登录启动等原生交互没有完成实机验收。

## 后续范围

M0 是第一条可运行链路，不代表 v2 全部完成。M1 仍需邀请配对、钥匙串、真实权限检查、截图核对、迁移与完整首次启动流程；P1 的审批、路径限制和屏幕提示仍未实现。统计只覆盖最近 200 条任务，不可用作全量计费数据。

当前命令具有本机用户权限；私有控制接口没有作为远端工具提供，但同用户 shell 仍可能访问它，不能把它称作 Agent 无法绕过的安全边界。
