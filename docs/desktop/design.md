# 桌面功能规划与交互设计 v2

状态：设计提案，替代 v1。记录日期：2026-10-04。设计稿截图与离线原型见 [目录说明](README.md)。

下文“核心改动”一栏列出 Rust 执行器需要新增的能力；界面画出来的功能不代表协议或执行端已经支持。

## 1. 用户的三个问题

Macrun 的用户在服务器上跑 Claude Code / Codex，把自己的 Mac 交给它编译、测试、点界面。装上桌面端的人，关心三个问题：

| 用户的问题 | v1 的回答 | v2 的回答 |
| --- | --- | --- |
| **能不能少折腾地连上？** | 设置页里填地址、选证书 | `macrun invite` 生成一次性配对码，粘贴即连，令牌进钥匙串，不再 scp |
| **Agent 此刻在我 Mac 上干什么？** | 今日任务 / 成功 / 失败三个大数字 | “现场”页：正在跑的命令、实时输出尾部、同步进度、桌面操作回放 |
| **出事了能不能马上停、能不能限制它？** | 只有“暂停接收” | 全部停止（菜单栏 / 屏幕悬浮条 / 全局快捷键）、工作目录白名单、风险命令确认、桌面控制总开关 |

v1 的核心问题：把“统计看板”当主角，但统计对这个产品几乎没有决策价值；同时缺了“信任与控制”。这是一个让远程 AI 操控本机的工具，用户最在意的是看得见、停得住、管得住。

## 2. 信息架构

```
菜单栏图标（状态色点：蓝=工作中 / 绿=空闲 / 黄=待确认 / 红=断线 / 灰=暂停）
└─ 面板：状态一句话 · 当前任务 · 待确认请求 · 暂停/全部停止/桌面控制 · 最近 3 条 · 打开主窗口

主窗口
├─ 现场        三条状态（连接 / 执行器 / 桌面控制）· 正在进行 · 工作区 · 刚刚
├─ 任务        状态筛选 · 搜索 · 列表 + 详情（含 unknown 解释与核对入口）
├─ 桌面控制    总开关 · 后端 · 本机条件检查 · 操作时行为 · 最近操作回放
└─ 设置与安全  安全边界 · 连接 · 通用 · 诊断

独立窗口：首次配对（配对码 → 检查连接 → 桌面控制可选）
屏幕层：桌面操作中的橙色描边 + 顶部悬浮条（不进入截图）
```

相对 v1 去掉的内容：首页三个统计大数字（降级为一行小字）、假进度条、混在产品里的平台／场景切换、快捷面板里的“今日统计”。

## 3. 设计原则

1. 回答一个问题：Agent 此刻在我的 Mac 上做什么。
2. 连接、执行器、桌面控制三条状态独立显示，不合并成一个“正常”。
3. 7 种真实任务状态全部可见：accepted、running、succeeded、failed、cancelled、timed_out、unknown。unknown 单独解释，不自动重放。
4. 不画无法测量的进度百分比，只显示阶段、已收文件数和已耗时。
5. 随时能停：菜单栏、屏幕悬浮条、全局快捷键三个入口。
6. 安全边界前置：工作目录白名单、风险命令确认、桌面操作开关。

## 4. 功能清单与优先级

P0 = Mac 首版必须有；P1 = 首版之后尽快；P2 = 视反馈。

### 4.1 连接与安装

| 功能 | 优先级 | 核心改动 |
| --- | --- | --- |
| 配对码：服务端 `macrun invite` 生成含地址、证书指纹、一次性码的 URI，桌面端粘贴后通过 QUIC 换取令牌 | P0 | 新增 invite 子命令和配对握手；一次性码 10 分钟过期 |
| 连接自检：UDP 可达、指纹一致、令牌、协议版本、试运行一条命令，逐项给出失败原因 | P0 | 复用现有 status / exec |
| 令牌存钥匙串，证书指纹固定 | P0 | worker 支持由桌面端注入凭据，不只读文件 |
| 检测旧 LaunchAgent `dev.macrun.worker` 并一键迁移（备份 plist） | P0 | 桌面端逻辑 |
| 手动填写地址 / 导入证书（兼容现有部署） | P1 | — |

### 4.2 现场（主页）

| 功能 | 优先级 | 核心改动 |
| --- | --- | --- |
| 三条状态独立：连接（延迟、稳定时长）、执行器（版本、协议、是否暂停）、桌面控制（后端、权限） | P0 | 本机状态 IPC，worker 推送事件 |
| 正在进行：命令全文、cwd、已用时、输出尾部实时滚动、取消 | P0 | 输出增量事件（output.log 已落盘，可 tail） |
| 同步进度：按“已收到 N / M 个文件 · 字节数”显示，不画百分比 | P0 | 已有 `Progress` / `Detail` 事件，转发到桌面端 |
| 工作区：同步过的 remote_root 列表、最近同步时间、失败原因，在访达 / 终端打开 | P1 | worker 记录同步目标 |
| “刚刚”时间线 + 一行当日汇总 | P0 | — |

### 4.3 任务

| 功能 | 优先级 | 核心改动 |
| --- | --- | --- |
| 7 种真实状态全部可见 | P0 | 已有 |
| unknown 专属说明：“可能已生效，不会自动重放”，提供“截一张当前屏幕核对” | P0 | 调用后端截图 |
| 按状态筛选，按命令 / 目录 / 编号搜索 | P0 | 本地索引 |
| 详情：cwd、耗时、退出码、任务编号、输出尾部、打开完整日志 | P0 | — |
| 失败 / 超时 / 未知时发系统通知，成功不打扰 | P1 | — |
| 记录保留策略（7 / 30 / 90 天），去重编号单独保留 | P1 | engine 清理任务目录 |

统计口径沿用 v1：按唯一任务编号计数，查询、心跳、重复请求不计；“今天”按本机时区和任务接收时间归属。

### 4.4 桌面控制

| 功能 | 优先级 | 核心改动 |
| --- | --- | --- |
| 总开关：关闭后 mcp.call 直接拒绝，命令和文件不受影响 | P0 | engine 检查开关 |
| 后端卡片：worker.toml 中的后端、会话号、工具数；重启后端时提示会话失效 | P0 | 已有 session generation |
| 本机条件检查：辅助功能、屏幕录制（实拍验证）、图形会话、防休眠 | P0 | 调后端 status / 实拍 |
| 屏幕悬浮条 + 橙色描边，显示当前动作和“停止” | P1 | 需要 mcp.call 的开始 / 结束事件 |
| 用户动鼠标 / 键盘时让出 30 秒 | P1 | 本机输入检测；只阻止新操作，不撤回已发出的 |
| 最近操作回放：按次序展示截图与点击位置 | P2 | worker 保留截图缩略图 |
| 在界面里添加 / 编辑 MCP 后端（写 worker.toml） | P2 | — |

### 4.5 安全边界（v1 没有）

| 功能 | 优先级 | 核心改动 |
| --- | --- | --- |
| 全部停止：取消所有运行中任务 + 暂停接收 + 关闭桌面控制；菜单栏、悬浮条、全局快捷键 ⌃⌥⌘. 三个入口 | P0 | engine 批量 cancel |
| 暂停接收新任务：运行中任务继续，新请求返回 `busy` | P0 | 现有 Fault 已有 `busy`，需接入请求入口 |
| 工作目录白名单：cwd、文件读写、同步目标必须在白名单内 | P1 | engine / files / sync 统一路径检查（注意符号链接与 `..`） |
| 命令确认三档：直接执行 / 风险命令先确认 / 每条都确认；菜单栏弹出，60 秒未处理视为拒绝 | P1 | 新增 `awaiting_approval` 状态与 `denied` 终态；Skill 同步更新 |
| 环境变量值不入记录 | P0 | 详情页只显示变量名 |

### 4.6 通用与诊断

| 功能 | 优先级 |
| --- | --- |
| 登录时启动；关闭窗口保留菜单栏；有任务时退出先询问 | P0 |
| 版本 / 协议 / 与服务器是否一致 | P0 |
| 查看日志、测试连通性、导出诊断包（不含命令输出、文件、截图、令牌） | P1 |

## 5. 视觉方向

- 中性暖灰 + 近黑主色，状态色只用于状态：蓝 = 运行、绿 = 成功、红 = 失败、琥珀 = 未知 / 待确认、灰 = 取消 / 超时。颜色之间同时拉开明度，不只靠色相区分。
- 正文 Geist + 苹方；命令和路径一律等宽（Geist Mono），便于阅读和复制。
- 原生 macOS 结构：侧栏 + 内容区、系统菜单栏面板；不使用渐变、玻璃拟态和装饰插画。
- 终端输出用深色块，是页面里唯一的深色元素，视线落在“正在发生的事”上。

## 6. 路线

1. **M0 技术验证（1–2 周）**：Tauri 托盘 + sidecar worker；本机 IPC（Unix socket，仅本用户）推送状态与任务事件；暂停 / 全部停止在 engine 里真正生效。
2. **M1 Mac 首版**：配对码、现场、任务、桌面控制（无回放）、设置（连接 / 通用 / 诊断）、LaunchAgent 迁移。全部 P0。
3. **M2 安全与体验**：工作目录白名单、命令确认、屏幕悬浮条、让出、通知、保留策略。全部 P1。
4. **M3 Windows 基础支持**：沿用 [执行计划](implementation-plan.md) 中的平台差异清单；桌面控制未验证前显示“不可用”。

## 7. 待确认问题

1. 命令确认会让 Agent 的调用“可能被人卡住”。是否接受新增 `awaiting_approval` / `denied` 两个状态，并相应更新 Skill？
2. 配对码需要服务端新增命令和握手流程，是否在 M1 做，还是先兼容“导入证书 + 令牌文件”？
3. 首版是否需要独立的“工作区”页面，还是现场页的一栏足够？
4. 退出、worker 崩溃后的清理与自动重启策略（沿用 v1 待确认项）。
